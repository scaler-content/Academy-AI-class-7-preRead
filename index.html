What Is an AI Agent?

From answering questions to taking action through tools and a decision-making loop

Class 7AI and AgentsPre-Read

1. Welcome

A chatbot usually responds to one message and waits. An AI agent can work toward a larger goal: it decides what to do next, uses tools, observes the results, and continues until the task is complete or it gets stuck. In this session, we move from the idea of an agent to watching one work and building one ourselves.

What to keep in mindThis pre-read introduces the ideas and vocabulary you will use in class. The hands-on build and detailed demonstrations happen during the session.

As you read, think about what an agent should be allowed to do, what information it needs, and where a person should remain in control.

2. The shift: from answering to doing

An assistant usually gives you an answer or suggestion. An agent is organised around a goal and can take steps toward it. It can decide which action to take, call a tool, inspect what happened, and choose what to do next.

Assistant

Usually responds to the immediate request with information or advice.

Agent

Works toward an outcome by selecting steps and using tools when needed.

Keep in mindKeep the distinction practical: an agent is not defined only by a clever prompt. Its ability to select actions and use tools is part of what makes it agent-like.

3. The Think–Act–Observe loop

An agent repeatedly moves through three stages. It thinks about the next step, acts by calling a tool or taking an available action, and observes the result before deciding what to do next.

Think

Choose the next step based on the goal and available information.

Act

Call a tool or perform an action.

Observe

Read the result and decide whether to continue, change direction, or finish.

Keep in mindTry tracing a simple task: find a product price, compare it with another price, and report which is lower. The agent may need more than one tool call.

4. Tools and MCP

A tool is a function an agent can call to retrieve information or perform an action. Its description helps the model understand what it does and when it may be useful. The Model Context Protocol (MCP) provides a standard way for AI applications to connect to external tools and context.

Tool

A callable capability with a purpose and an input/output contract.

MCP

A protocol for connecting AI applications with tools and context.

Keep in mindConnecting a tool does not mean the model knows every detail of its implementation. Clear names and descriptions help the agent choose appropriately.

5. Build, test, and set boundaries

The class moves from observing an agent to building a shop assistant that looks up product prices and answers a multi-step question. It also examines failures, including poor tool use and agents that do not stop as expected.

Goal

What outcome should the agent achieve?

Tools

What external information or actions are available?

Instructions and boundaries

What should the agent do, avoid, or do when it cannot complete a task?

Keep in mindBefore building, sketch the agent's goal, tools, instructions, and boundaries. Also ask whether the task actually needs a tool or can be answered directly.

6. A Few Terms to Know

These terms will help you follow the explanations and activities in the session.

AI agentA system built around a model that can choose steps, use tools, observe results, and continue working toward a goal.
ToolA function an agent can call to perform an action or retrieve information, with a description that helps the model decide when to use it.
Think–Act–ObserveThe recurring agent loop: decide what to do, perform an action, inspect the result, and decide what to do next.
MCP (Model Context Protocol)A standard protocol for connecting AI applications to external tools and context.
What you’ll walk away withYou’ll be able to explain what makes a system an agent, describe the Think–Act–Observe loop, identify the role of tools, memory and MCP, and sketch a simple agent before implementing it.

A Few Ideas to Keep in Mind

You should be comfortable with the idea of an LLM responding to prompts and with the basic workflow concepts introduced earlier. You do not need to have built an agent before this class.
